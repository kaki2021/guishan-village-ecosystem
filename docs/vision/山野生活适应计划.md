# 归山村落 · 小程序「山野生活适应计划」功能规划

> 配套《对外展示·为什么与文案》。那份讲「为什么」,这份讲「具体做什么、按什么顺序加进小程序」。

---

## 0. 一句判断(先看这个,别跳)

这 8 类玩法**不是 8 个功能**。它是:

- **一条漏斗**:游客 → 共建者(就是我们一直说的那条「匝道」),用四个入口表达;
- 加上 **两三个真·新系统**(任务卡 / 积分 / 认养)。

最大的风险是把它读成「要做 8 件事」——你自己的文档结尾就在防这个(「别做成认养 / 卖菜平台」)。所以这份文件只干三件事:**把 8 类拆开 → 标清哪些是「包装你已有的东西」(几乎零工程)、哪些是「真要新建」(排队再做)→ 给一条只建一次的进度主干。**

整件事的定盘星还是你文档里最对的那句,钉死别松:

> **客户买的不是菜、不是房,是「我在山里有一块正在长的东西、一个能回去的地方、一群慢慢熟起来的人」。**

任何功能,只要把这句稀释成「卖菜 / 攒分换券」,就是做歪了。

---

## 1. 它和之前那套「为什么」是什么关系

一句话:**它是「为什么」长出来的价签和按钮。**

- **about** 讲为什么(时代 / AI / 地板)
- **适应计划** 讲你具体能来干嘛、怎么一步步深进来(四个入口)
- **join** 讲想真正留下来怎么办

漏斗串起来:
`about(为什么)→ 适应计划(四入口)→ 报名 / 旅人证(身份在长)→ join(深度共建)`

你文档那句「提前练习一种以后可能用得上的生活」,正是我们那句「趁城市还需要你时提前建好地板」的**消费品版**。方向没变,这是落地。

---

## 2. 主干:先立四个入口(别先做玩法)

四个入口是骨架。**先把骨架立起来,玩法是后面往骨架上挂的肉。**

| 入口 | 是什么 | 靠哪个已有能力 |
|---|---|---|
| **先来住** | 体验卡、适应包 A | = `activities` + `enrolls`（报名），已有 |
| **学一点** | 山村技能小课 | = `activities`（重复活动），已有 |
| **认一份** | 认养一块地 / 一窝鸡鸭鹅 | = 新系统(排最后) |
| **留下位置** | 值日、任务、会员、试住营 | = 混合(部分已有、部分新建) |

**立主干 = 首页 / 导航按这四个入口重组,每个入口先放「已有的报名活动」,空的先留位。这一步不需要任何新功能。** 先有骨架,用户才知道自己站在漏斗哪一格。

---

## 3. 分三批做(关键纪律:别一次全上)

### 🟢 第 0 批 · 零工程,纯包装,这周就能上

本质:把你**已经做好的报名闭环**,包装成有记忆点的产品。**是写文案 + 上架,不是建功能。**

- **山野生活体验卡**(一日山民 / 周末归山)→ 一个单次 `activity`
- **山村技能小课**(山泉 / 柴火 / 菜地 / 家禽 / 山路 / 急救 / 厨房)→ 一组重复 `activity`
- **一周山居适应营** → 重复 `activity`;**这个优先级最高**,因为它是「游客 → 共建者」的关键筛子产品
- **提前适应包 A / B / C** → 把上面打包成轻 / 中 / 深三档

> **判断:这一批投入产出比最高。你最该先上的不是任何新系统,是「把现有报名当产品卖」。** 先用这批测「到底有没有人买、买哪档」,再决定下面的新系统值不值得建。别系统没人用就先把它造出来。

### 🟡 第 1 批 · 轻量,复用你已有的身份系统

- **山野生活会员等级**(初来者 → 山中朋友 → 值日旅人 → 山田认养人 → 山房共建人 → 归山合伙人)
  → **复用现有「荣誉头衔」**,只需定义阶梯 + 每级解锁条件 + 展示。不是新系统。
- **周末值日生**(今日水官 / 火官 / 菜官 / 禽官 / 山路官 / 记录官)
  → **复用现有「山野章 / 章」系统**做「今日身份」,完成给一枚章。轻。

> **判断:这两个几乎是「给已有系统配数据」,不是从零建。会员等级尤其值得早做——它把零散的报名,变成「我在往上走」的连续感,正好承接第 0 批卖出去的体验。**

### 🔴 第 2 批 · 真·新系统,值得做,但排队、一次一个

这三个每个都是**新数据模型 + 新页面 + 新规则**,别同时上(理由见第 4 节):

- **山野任务卡 / RPG**(接你原来的「旅人公会」方向)
- **山中账户 / 贡献积分**
- **认养**(山田 / 鸡鸭鹅)

## 4. 三个新系统:做之前必须想清楚的判断与坑

**① 只建一条进度主干,别建四条。**
你现在手里有四套「往上走」的机制想同时存在:荣誉头衔、会员等级、任务进度、贡献积分。**四条并行 = 用户搞不清自己在攒什么 = 四个都半生不熟。** 选一条当主干(建议**会员等级**,它最能表达「我和这座山的关系在变深」),其余当**纹理**挂上去;验证主干真能拉人之后,再一个一个加。

**② 积分换钱要克制。**
你文档里「积分换房费抵扣」——一旦积分 = 钱,你建的就是个会员卡积分体系,「我在山里留下了劳动」会被「我在刷折扣」冲淡。兑换主要给**象征 / 体验**(徽章、一顿共食、深度路线、认养优先权);money-equivalent 的克制。这跟你内部那条「金额永远代码算、AI 不碰」是同一种洁癖:别让 engagement 分悄悄变成货币。

**③ 对外积分别去碰「工分」那套(澄清:不是这个 app 的事)。**
说明一下:这个**对外 app 本来就不碰工分**——工分 / 股 / 金库 是**另一个独立的内部工具**,跟对外获客这套是两回事。所以这里没有什么「内部接缝」要焊。唯一剩的轻提醒:哪天对外真做积分,让它老实当个**顾客互动分**(玩、换体验),别去模仿那个独立内部工具里「工时 × 强度」的工分逻辑,也别让顾客误以为攒对外积分 = 攒劳动股权。两套东西、两个工具、两拨人,别在叫法上让人混了。

**④ 认养别打头阵,否则必滑成卖菜。**
这正是你自己的警告。认养如果先于「体验 + 会员」主干上线,你会被发货 / 对账 / 物流拖进电商。让认养**跟在主干后面**:先有「我和这座山有关系」的人,再给他「认一块地」去深化关系,而不是反过来用认养拉新。

**⑤ 会员顶层是「对外」交给「对内」的接力点。**
「归山合伙人:长期参与经营 / 治理」——这一级已经走出对外获客的范围,踩进你那个**独立内部工具**的世界(合作社 / 分配机制 / 只有劳动者投票)。要划清:对外会员等级**到哪儿为止**,从哪儿开始把人交接给内部那套共建者 / 工分体系。别让一个「在对外 app 买了很多体验包」的人,以为自己自动获得了治理权或股权——那是另一个工具、另一道门里的事。

## 5. 你往里加新东西时,先过这个筛子(你说要补内容)

之后再想到新玩法,别先问「做不做」,先丢进这四关:

1. **它落在四个入口的哪个?**(先来住 / 认一份 / 学一点 / 留位置)——落不进,先怀疑它跑题了。
2. **它是「包装已有报名」还是「要新建系统」?** 前者 → 第 0 批直接上;后者 → 排第 2 批。
3. **它会不会把「我在山里有一块正在长的东西」稀释成「买东西 / 刷分」?** 会,就砍或改。
4. **它进哪条进度主干?** 会不会又开了第五条平行的「往上走」?会,就并进主干,别新开。

过四关的留下;没过的,要么改、要么后置。**这个筛子你自己就能用,不用每次来问我——你比我更知道哪条玩法是真有记忆点,还是只是又一个好看的功能。**

---

## 6. 落到现有页面 / 数据(轻提示,非详细设计)

- **四入口** → 首页(`index`)重组,或新增一屏;入口应从 about 末尾、首页理念卡附近接上(承接「为什么」)
- **体验卡 / 小课 / 适应营 / 适应包** → 复用 `activities` + `enrolls`，零新建
- **会员等级** → 复用 `users` 的荣誉头衔 + 一张等级规则表
- **值日生** → 复用 `records` / 章系统,或挂在 `session` 上做「当日角色」
- **任务 / 积分 / 认养** → 各自新集合,排到第 2 批再设计数据模型

## 附:一句收口

这份文档真正想拦住的,是「拿到 8 个亮点子就想全做」的冲动。**你已有的报名闭环 + 身份系统,能零成本撑起这 8 类里的一大半;真要新建的只有三样,而那三样越晚做、想得越清楚,越不容易把你拖进「卖菜 / 刷分」的沟里。** 先卖体验、先立会员主干,让真人用脚投票,再决定下一块肉挂哪儿。
