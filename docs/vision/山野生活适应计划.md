# 归山村落 · 山野生活适应计划

> 本文与《项目理念与参与指南》配套使用。前者说明归山村落为什么存在以及可以怎样参与，本文进一步说明不同参与方式的产品安排和建设顺序。

---

## 1. 核心判断

目前提出的八类产品设想，不应被理解为八个需要同时开发的独立功能。它们主要由两部分组成：

- 一条从短期体验走向长期共建的参与路径；
- 任务、积分和认养等少量需要独立开发的新系统。

现阶段最重要的工作，不是一次性增加大量功能，而是先把已有的活动报名、成员身份和参与记录组织成一条清楚的路径，让用户知道自己可以从哪里开始，以及下一步能够怎样继续参与。

整个产品设计应围绕下面这句话展开：

> **客户买的不是菜、不是房，而是“我在山里有一块正在生长的东西、一个可以回去的地方、一群慢慢熟悉起来的人”。**

如果一项功能最终只剩下卖农产品、累计积分或兑换折扣，它就偏离了归山村落原本希望建立的人与土地、人与地方、人与人之间的长期关系。

---

## 2. 与项目整体叙事的关系

《项目理念与参与指南》负责解释项目的背景、方向与价值；山野生活适应计划负责把这些理念转化为具体的参与方式；加入与共建页面则承接希望长期驻留或深度参与的人。

完整路径可以概括为：

`了解项目理念 → 选择参与方式 → 报名并形成个人参与记录 → 申请长期驻留或共同建设`

对应到现有小程序页面：

- `about`：介绍项目为什么存在；
- 山野生活适应计划：说明可以参加什么，以及不同参与方式之间的关系；
- 活动报名与旅人证：记录实际参与过程；
- `join`：承接长期驻留、合作与共建申请。

“提前练习一种以后可能用得上的生活”，是这套计划最直接的表达。它不是脱离原有理念的新产品，而是把理念转化为可以实际参加的活动和长期参与路径。

---

## 3. 四类参与入口

小程序可以先围绕四类参与入口重新组织内容。每个入口都使用完整、明确的名称，不再使用容易产生歧义的简称。

| 参与入口 | 主要内容 | 与现有功能的关系 |
| --- | --- | --- |
| **短期山居体验** | 一日体验、周末山居、一周适应营和不同深度的体验方案 | 可直接使用 `activities` 与 `enrolls` 完成活动展示和报名 |
| **山村生活技能学习** | 山泉、柴火、菜地、家禽、山路、急救和厨房等生活技能课程 | 可使用重复活动功能组织课程 |
| **土地与家禽认养** | 认养一块土地，或参与鸡、鸭、鹅等家禽的长期照料 | 需要独立设计认养记录、进度展示和履约规则，后期建设 |
| **长期驻留与共同建设** | 周末值日、任务参与、阶段性试住、长期驻留和共建申请 | 可复用部分身份与记录功能，其余能力分阶段补充 |

首页和主要导航应先围绕这四类入口整理。第一版可以只放入现有活动和报名内容；暂时没有内容的入口可以保留说明，不必为了填满页面而提前建设新系统。

---

## 4. 分阶段实施方案

### 第一阶段：整理并发布现有活动

这一阶段基本不需要新增系统功能，重点是把已经能够报名的活动整理成容易理解、方便选择的产品。

- **山野生活体验**：包括一日山民、周末归山等短期活动，可作为单次活动发布；
- **山村生活技能课程**：围绕山泉、柴火、菜地、家禽、山路、急救和厨房等内容，建立可重复报名的课程；
- **一周山居适应营**：作为从短期游客走向持续参与者的重要活动，优先整理和发布；
- **分级体验方案**：将已有活动组合成轻度、中度和深度三类参与方案，帮助不同需求的人选择。

这一阶段的目标，是先验证哪些活动真正有人参加、参与者愿意停留多久，以及哪些内容能够促成再次到访。只有在真实使用结果明确以后，才有必要继续开发新的系统。

### 第二阶段：完善持续参与的身份记录

这一阶段主要复用现有的旅人身份、荣誉头衔和山野章，不需要从零建设一套新的账户体系。

#### 山野生活参与等级

可以根据实际参与深度设置以下等级：

`初来者 → 山中朋友 → 值日旅人 → 山田认养人 → 山房共建人 → 归山合伙人`

需要明确每一级的进入条件、展示方式和对应权益。等级的作用不是制造消费门槛，而是让参与者看见自己与这个地方的关系正在逐步加深。

#### 周末值日角色

可以设置水务、柴火、菜地、家禽、山路和记录等当日角色。参与者完成当天工作后获得相应的山野章，形成可回顾的参与记录。

这两项功能都可以在现有身份和记录体系上扩展。它们的重点是增加连续性，不是另外建立一套相互竞争的成长机制。

### 第三阶段：逐项建设独立系统

以下三类功能需要新的数据结构、页面和业务规则，应逐项设计和验证，不宜同时开发：

1. **山野任务系统**：承接原有“旅人公会”和任务卡的设想；
2. **参与贡献积分**：记录外部参与者在活动和公共事务中的贡献；
3. **土地与家禽认养系统**：记录认养对象、照料过程、阶段变化和双方责任。

每次只建设一项，完成实际使用验证以后，再决定是否进入下一项。

## 5. 建设新系统前需要明确的边界

### 5.1 只保留一条主要成长路径

荣誉头衔、参与等级、任务进度和贡献积分都可以表达参与程度，但不能同时成为四套并行的成长体系。体系过多会让参与者无法理解自己正在积累什么，也会增加运营和维护成本。

建议以“山野生活参与等级”作为主要路径，因为它最能表达一个人与归山村落的关系变化。任务、山野章和积分只作为参与记录和辅助信息，不再各自建立一套独立等级。

### 5.2 积分不应直接等同于货币

如果积分主要用于抵扣房费或兑换现金价值，系统很容易变成普通会员积分，劳动和参与的意义也会被折扣机制取代。

积分更适合兑换具有项目特色的体验，例如纪念徽章、一次共同用餐、深度山野路线或认养优先权。涉及费用的内容应由明确的价格和财务规则处理，不应由积分体系模糊替代。

### 5.3 对外参与积分与内部劳动记录必须分开

对外小程序面向游客、旅人和潜在共建者；内部运营工具用于记录工时、强度、金库、分配和治理。两套系统服务不同人群，也承担不同责任。

将来如果增加对外积分，它只能表示活动参与和互动情况，不能套用内部“工时 × 强度”的计算方式，也不能让用户误以为外部积分能够自动转化为工资、股权、分红或治理权。

### 5.4 认养系统不宜作为第一入口

认养涉及持续记录、履约、实物分配、发货、对账和售后。如果在体验关系尚未建立以前首先推广认养，项目很容易被日常物流和农产品销售牵着走，最终变成普通的认养或电商平台。

更合适的顺序是：先让参与者来到现场，形成对地方和人的真实认识；再向有持续参与意愿的人开放认养，用认养深化关系，而不是单独依靠认养吸引新用户。

### 5.5 对外会员与内部共建之间需要明确交接条件

“归山合伙人”已经涉及长期经营、分配和治理，超出了普通对外会员的范围。需要明确对外参与等级在哪一级结束，达到什么条件后，才可以申请进入内部共建体系。

购买过较多活动、拥有较高外部等级或积累了较多积分，都不能自动获得股权、分红权或治理权。长期共建应通过单独申请、实际劳动、共同协商和正式协议确认。

## 6. 新内容与新功能的筛选标准

以后增加活动或功能时，可以依次检查以下四项：

1. **它属于哪一种参与入口？** 需要明确归入短期山居体验、山村生活技能学习、土地与家禽认养，或长期驻留与共同建设；无法归类的内容应重新判断是否偏离项目方向。
2. **它能否使用现有功能完成？** 可以通过活动和报名实现的内容，直接使用现有系统；确实需要新的数据、页面和规则时，再进入独立开发计划。
3. **它是否有助于建立长期关系？** 如果最终只增加商品销售、积分兑换或短期流量，应调整方案或降低优先级。
4. **它怎样进入主要成长路径？** 新功能应补充现有参与等级和记录体系，不应再建立一条相互独立的成长路线。

通过这四项检查，可以避免功能不断增加、参与路径却越来越模糊。

## 7. 与现有页面和数据的衔接

| 内容 | 建议实现方式 |
| --- | --- |
| 四类参与入口 | 重组首页 `index`，或增加一页独立入口；同时从 `about` 页面末尾承接项目理念 |
| 山野生活体验、技能课程和适应营 | 复用 `activities` 与 `enrolls`，不新增数据模型 |
| 山野生活参与等级 | 复用 `users` 中的荣誉头衔，并增加清楚的等级规则 |
| 周末值日角色 | 复用 `records` 与山野章，或在活动场次 `session` 中记录当日角色 |
| 山野任务系统 | 进入第三阶段后单独设计任务数据、状态和页面 |
| 参与贡献积分 | 进入第三阶段后单独设计积分来源、记录和使用边界 |
| 土地与家禽认养 | 进入第三阶段后单独设计认养对象、周期、责任和进度记录 |

---

## 8. 实施原则

现有的活动报名和身份记录，已经能够支撑大部分早期产品设想。近期应先把这些能力整理成清楚的参与路径，通过真实报名、到访和持续参与情况判断需求。

任务、积分和认养都可以成为后续的重要能力，但应在参与路径稳定以后逐项建设。先让人真正来到山里，认识这里的土地与成员，并愿意再次回来；再用新的系统帮助这种关系持续发展。
