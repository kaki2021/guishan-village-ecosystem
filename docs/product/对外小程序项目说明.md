# 归山村落 · 对外小程序项目说明（公开整理版）

> 本文档用于技术交接与运营维护。本版已同步到「多类型筛选 + 内容合并 + HTML 安全化 + 权限分组 + 活动展示改造 + 废弃清理」完成后的状态。
> 这是「对外获客」统一 app，与内部运营工具（工分/股/金库）是两套独立东西，互不相关。

---

## 0. 现状速览

- 微信小程序**云开发**（小程序代码在 `miniprogram/`，云函数在 `cloudfunctions/`）。
- 多节点对外获客 app：壳=归山村落，金山书院 / 观天瀑是节点(venue)。理念=新村落文明（旅养教医农文六板块）。
- 生产部署曾以正式主体上线并完成备案；本仓库不包含生产 AppID、云环境 ID、订阅模板 ID、密钥或私人联系方式。
- 仓库规模：**云函数目录 51 个、已注册页面 22 个**；富文本使用 `mp-html` 组件。

## 1. 沟通与原则（重要）

- 维护原则：先明确关键判断与取舍，再实施代码；控制功能边界；诚实标注限制；大重构分阶段部署验证，不与无关功能混做。
- 配色：壳主色 `#5f7060`；观天瀑 `#E8A33D`，金山书院 `#9c5a3c`。
- 合规红线：不沾玄学/疗效，不用功法做栏目名，宗教词淡化。
- **UGC 合规边界（命脉，别破坏）**：普通用户（少灵）不能发任何公开内容；公开发布只属于经运营方授权的成员能力。详见 §9。

## 2. 技术架构与铁律

- `project.config.json`：miniprogramRoot `"miniprogram/"`、cloudfunctionRoot `"cloudfunctions/"`。
- 每个云函数自带 package.json（wx-server-sdk ~2.6.3）；碰开放接口（msgSecCheck/mediaCheckAsync/subscribeMessage）的才给 config.json；一律「云端安装依赖」部署。删云函数要本地+云端两边都删。
- **环境变量每个云函数各配各的不共享**。AI 走火山方舟 Ark（ARK_API_KEY/ARK_MODEL/ARK_VISION_MODEL）。
- 每个云函数 index.js 第一行注释 `// ===== 云函数 xxx —— 用途 =====`。
- **新增集合必须先在控制台手动建表**，否则 `collection not exists`（activities/enrolls/pages 都踩过）。
- **cloud:// 图片铁律**：cloud:// 文件ID 不能直接进 `<image>`/HTML（报 500），展示前必须服务端 `getTempFileURL` 转 https；HTML 内 cloud:// 用正则替换。编辑器存原始 fileID、另给临时 url 仅预览（约 2h 过期，别存回库）。
- **富文本 mp-html**：组件在 `components/mp-html/`（9文件），app.json 全局注册。理念页/节点介绍/活动介绍/文章正文都用它渲染 HTML。让 AI 生成 HTML 时注明"用于微信小程序 mp-html 组件，避免不支持标签和 JS"。**所有存 HTML 的函数已加白名单清洗**（见 §11）。
- **全局 input 截断已根治**：app.wxss 有全局规则强制所有 input `height:80rpx!important; line-height:80rpx!important; padding 上下 0`。长文用 `<textarea maxlength="-1" auto-height>`。
- 微信 `<button>` 默认样式破坏布局→用"view 卡片+内部透明 button 覆盖层"。
- wx.showModal 在本项目曾失灵，遇到优先换方案。
- **wxml 里写 `数组.indexOf()` 表达式渲染不稳定**——节点多类型标签选中态曾因此不变色。改用 js 预计算每项的 `on` 标记，wxml 直接用 `item.on`。（踩过，重要）
- **地图零位置权限**：节点地图用 `<map enable-satellite>` 卫星图（不需权限）+ openLocation 导航。已删 chooseLocation/getLocation 及所有位置声明。节点经纬度后台手填。

## 3. 数据库集合（当前 12 个 + 4 个废弃旧集合）

**活跃：**
1. **users**：`_openid`/`nickName`/`avatarUrl`/`roles:[{roleKey, venueId, referrer?, referredAt?}]`。referrer=引荐人。
2. **roles**：`key`/`name`(显示称号)/`perms[]`/`scope`。六称号见 §6。
3. **venues**（节点）：`name`/`brandColor`/`cover`/`intro`/**`venueTypes`(数组,多类型)**/`venueType`(旧单类型,兼容保留)/`detailHtml`(HTML图文,已清洗)/`address`/`modules`/`order`/`status`('active'|'pending')/`lat`/`lng`/`applicantOpenid`。
4. **categories**：`kind`('wild'|'activity'|'content'|'venue')/`key`/`name`/`icon`/`order`/`status`/`source`。节点类型从 venue 组动态读，**用户手动加不预设**。
5. **activities**（统一活动）：`venueId`/`title`/`category`/`cover`/`introHtml`(已清洗)/`capacity`(默认名额)/`status`('open'|'draft')/`repeat`('once'|'weekly'|'daily'|'monthly')/单次 `date`/重复 `weekday`|`monthday`/`clock`/`recurrenceText`。
6. **enrolls**（报名）：`_openid`/`activityId`/`date`(具体场次)/`clock`/`title`/`venueId`/`name`/`phone`/`status`('joined'|'cancelled')/`subscribed`(订阅提醒)/`notified`(已推)/`createdAt`。场次 = activityId+date，名额按此组合计数。
7. **contents**：`venueId`/`type`/`title`/`cover`/`bodyHtml`(已清洗)/`solarTerm`/`status`。
8. **records**（山野记录）：`_openid`/`categoryKey`/`text`/`images[]`/`status`('public'|'checking'|'rejected')/`imgChecks[]`/`likeCount`。**首页"山野近况"区现读此集合**（村子近况已并入）。
9. **joins**（加入意向）：`_openid`/`kind`('reside'|'partner'|'node')/`name`/`wechat`/`phone`/`message`/`skills[]`/`status`。
10. **pages**（理念页）：`key`/`navTitle`/`cardTitle`/`cardSub`/`html`(已清洗)/`order`。
11. **uploads**（文件台账）：记录云文件的业务来源、使用状态和清理状态。
12. **counters**（序号计数）：用于一次性成员维护与编号辅助。

**废弃旧集合（测试数据可清空，当前代码已无读写）：** sessions、series、signups、**moments**（村子近况已并入 records）。

## 4. 云函数（按用途）

### 活动（统一模型，核心）
- **adminSaveActivity** [msgSecCheck] — 统一活动保存（单次/重复合一、HTML介绍已清洗、默认名额、节点权限校验）。
- **adminListActivities** — 后台列节点下活动。
- **listActivities** — 公开：活动展开成未来4周场次（已较少用，首页/节点页改为只显示活动规律不展开）。
- **getActivitySession** — 传 activityId（不传 date），返回活动信息 + 未来4周可报场次列表（每场含余位/是否已报）。**详情页核心**。
- **enrollActivity** [msgSecCheck] — 报名某场次（名额校验+防重复，存 subscribed 订阅标记）。
- **cancelEnroll** — 取消报名。
- **adminActivitySignups** — 后台看某活动报名名单（按场次日期分组，需节点权限）。
- **getMySignups** — 我的报名（读 enrolls）。
- **remindEnrolls** [subscribeMessage.send，带定时触发器每10分钟] — 给"开始前约2小时、已订阅、未推过"的报名推送提醒。模板 ID 通过云函数环境变量 `SUBSCRIBE_TEMPLATE_ID` 配置；字段 thing22=活动名/time24=时间/thing35=地址/thing4=温馨提示。

### 节点 + 地图 + 审核
- **getVenueHome** — 节点详情（detailHtml + 活动只显示规律不展开）。
- **getVenueAdmin** — 后台读节点供编辑（含 venueTypes 数组回显、lat/lng）。
- **adminSaveVenue** [msgSecCheck] — 存节点（封面/简介/**venueTypes多类型**/detailHtml已清洗/经纬度）。
- **getMyVenues** — 后台"我能管的节点"（玄灵/止灵=全部，亓灵=自己负责的）。
- **applyNode** [msgSecCheck] — 亓灵及以上申请加节点（建 pending）。
- **adminPendingNodes** — 列待审节点（需 manageAll）。
- **reviewNode** — 审核：通过(active+申请人设为该节点亓灵)/驳回(删除)。需 manageAll。

### 成员 + 分级授权
- **getMyProfile** — 旅人证：rankTitle + canManage/canManageMembers/canPost/canReviewNodes/canApplyNode + 山野章。
- **listMembers** — 列成员（玄灵/止灵看全部，亓灵只看自己节点仓灵），返回引荐人昵称 + me 授权能力。
- **setMemberRole** — 分级授权设称号（见 §6；仓灵记录引荐人）。
- **abdicate** — 玄灵自助退位转襾灵（唯一玄灵时拦）。

### 理念页（HTML 可增删排序）

### 内容（HTML 化）

### UGC（过审关键）

## 6. 六称号 + 分级授权 + 后台权限分层

| 称号 | roleKey | perms | 能力 |
|---|---|---|---|
| 少灵 | (无) | — | 看、报名；不能发任何内容、无后台 |
| 仓灵 | member | postMoment | +发山野记录；无后台；记引荐人 |
| 亓灵 | steward | manageVenue | 管**自己节点**活动/内容/资料；给自己节点设仓灵；申请加节点 |
| 止灵 | manager | manageAll, manageMembers | 全局管理+成员管理+节点审核 |
| 玄灵 | chief | manageAll, manageMembers | 最高，设玄灵/襾灵、可退位 |
| 襾灵 | elder | viewAll | 退位荣誉，只读且受保护 |

**setMemberRole 授权规则**：玄灵可设全部；止灵可设少灵/仓灵/亓灵(任命亓灵绑节点)；亓灵只能给自己节点设/收仓灵并记引荐人；玄灵/襾灵受保护。

**后台入口权限分层（admin 页，分两组）**：
- **内容管理**：节点资料(亓灵可见自己的)、理念内容(止灵+)、分类管理(止灵+)。
- **人与节点**：成员管理(亓灵可见自己节点)、加入意向(止灵+)、节点审核(止灵+)、申请加节点(亓灵+)。
- 仓灵/少灵 → me 页无后台入口，进不去。
- **双保险**：前端藏入口 + 后端全局函数校验 manageAll，亓灵(manageVenue)绕过也被拒。
- admin 页节点列表用 getMyVenues（亓灵只列自己节点）。

## 8. 活动展示 + 报名提醒

**活动展示（已改造）**：首页/节点页**一个活动只显示一张卡 + 规律文案**（如"每周六 07:00"），不再展开成多张场次卡。点进详情页(session)才展开未来4周可报场次，**每场独立报名/取消按钮**（各自余位），能报多场。单次活动详情页只一场直接报。跳转只带 aid 不带 date。

**报名提醒（订阅消息，开始前2小时）**：报名时 requestSubscribeMessage 弹授权，enrolls 存 subscribed。一次性订阅=授权一次推一条。remindEnrolls 定时触发器每10分钟跑，找"距开始110~130分钟、subscribed、未notified"的推送。取消报名自动不推。

## 9. UGC 合规边界（命脉，别破坏）

公开发布能力必须与实际运营资质和类目保持一致。当前产品采用“普通访客只浏览与报名、经人工授权的成员才可发布”的明确边界：
- submitRecord 加 canPost 校验（仅仓灵及以上）。
- 前端：少灵无任何发布入口（wild 页"+记一条" wx:if=canPost）。
- 仓灵必须由运营方手动授予，不能在注册后自动获得。
- 提审材料应如实说明："普通用户（未授权）仅可浏览与报名，无任何内容发布入口；内容发布与后台管理需运营方授权。"
- 活动报名不算 UGC。
- **绝不能做**：公开留言墙/求助帖/人人可发社区（触发社交类目）。

## 11. HTML 安全化（重要）

富文本输入属于重点安全边界。4 个保存函数（savePage/adminSaveContent/adminSaveVenue/adminSaveActivity）会在入库前调用白名单清洗逻辑，剥离 script/iframe/style/object/embed/link/meta 标签、所有 on* 事件，以及 javascript:/data:text/html/vbscript: 协议，只保留业务需要的基础排版标签。

建议继续采用最小标签白名单，并在每次调整富文本渲染或审核策略后做真机与提审验证。如果未来不再需要自由 HTML，优先迁移到结构化内容区块。

## 13. 踩过的坑（务必记住）

1. 新增集合要先控制台建表，否则 collection not exists。
2. cloud:// 图片必须服务端转 https；编辑器存 fileID、预览用临时 url（会过期别存回库）。
3. 大重构分回合做，每回合发文件让用户部署验证。
4. 微信 button 默认样式破坏布局→透明覆盖层；showModal 会失灵→换方案；input 截断→app.wxss 全局规则根治。
5. **wxml 里 `数组.indexOf()` 表达式渲染不稳定**→改 js 预计算 on 标记(item.on)。节点多类型选中态踩过。
6. 地图选点要申请地理位置接口+隐私声明，已弃用改手填经纬度；展示/导航不需权限。
7. 订阅消息一次性订阅=授权一次推一条；字段 key 不连续(thing22/time24/thing35/thing4)，按模板实际 key 填。
8. 删云函数/页面后，要清 app.json 注册和所有调用处（about/adminTags/signup/moments 都清过）。删云函数本地+云端两边删。
9. 权限前端藏入口 + 后端校验双保险；亓灵只能管自己节点。
10. **任意 HTML 输入是安全风险点**，已加白名单清洗；每次调整后都要重新做真机与审核验证。
